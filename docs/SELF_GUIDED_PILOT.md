# Nibiru Debug Desk: 15-minute self-guided pilot

This protocol is for developers willing to test the independent Nibiru Debug Desk with public Nibiru EVM Testnet 2 data. It is an unpaid technical-feedback exercise, not a promotion or investment activity.

## Before you start

- Allow 15 minutes on a desktop browser.
- Use Testnet 2 and public chain data only.
- Never share a seed phrase, private key, personal identifier, or mainnet funds.
- A wallet connection and transaction signature are not required.

## Run the test

### 00–02 minutes: confirm the boundary

Read the safety note in the Debug Desk. Confirm that you understand the tool is read-only, independently maintained, and not an official Nibiru support product.

### 02–05 minutes: verify the network

1. Open the live Debug Desk.
2. Refresh **Network health**.
3. Confirm the RPC is responding and the reported chain ID is `6911`.
4. Note anything unclear, slow, or inconsistent.

### 05–09 minutes: inspect public data

Use one public Testnet 2 address or transaction hash. Check whether the result explains the account or transaction state clearly enough to choose a sensible next step.

### 09–12 minutes: build a report

Describe the observed result and exact reproduction steps. Copy or download the generated Markdown support report. Remove anything private before sharing it.

### 12–15 minutes: report the result

Open the structured pilot-feedback issue. Record:

- what you tested;
- what worked;
- what failed or confused you;
- one concrete improvement;
- an optional public testnet or issue link.

## Completion standard

Checking every box is not proof by itself. A pilot run is counted only when it includes a reproducible report, a public issue, or another public testnet artifact that can be reviewed. A negative result is still useful evidence.

## Evidence and consent

- Publish aggregate counts, never participant identities by default.
- Do not publish a tester's screenshot, name, or quote without explicit permission.
- Label planned sessions as planned; do not present estimated outcomes as completed.
- Preserve failed or critical feedback instead of selecting only positive comments.
